# Projects Directory Guide

This directory contains all project-specific data, inputs, and workflow execution results.

---

```

├── stephenson_rife/          ✅ Complete example
├── galfand_berger/           ✅ Complete example
├── _template_project/        📝 Use this template for new projects
└── README.md                 (this file)
```

---

## Creating a New Project

### Step 1: Copy Template
```bash
cp -r _template_project new_project_name
cd new_project_name
```

### Step 2: Update Files

**Update `README.md`**:
```markdown
# [Project Name]

**Client**: [Client Name]
**Project Manager**: [PM Name]
**Status**: [Status]
**Go-Live Date**: [Date]
**Timeline Status**: [ON_TRACK/AT_RISK/DELAYED]

## Project Overview
[Brief description]

## Key Dates
- [Date]: [Event]

## Team
- Project Manager: [Name]
- Dev Lead: [Name]
- QA Lead: [Name]

## Notes
[Any project-specific notes]
```

**Update `metadata.json`**:
```json
{
  "project_name": "Your Project Name",
  "practice": "PMO",
  "client_name": "Client Name",
  "project_manager": "PM Name",
  "go_live_date": "2026-09-15",
  "status_date": "2026-08-05",
  "timeline_status": "ON_TRACK",
  "budget_total": "$500,000",
  "budget_spent": "$200,000"
}
```

### Step 3: Add Input Files

**In `input/` folder**:
1. Copy meeting transcript to `transcript.txt`
2. Update `metadata.json` file (or move existing one)

### Step 4: Run Pipeline

```bash
# From production root directory
python run_pipeline.py \
  --transcript projects/new_project_name/input/transcript.txt \
  --metadata projects/new_project_name/input/metadata.json \
  --project-name "Your Project Name"
```

Pipeline will create `workflow_execution/` folder automatically.

## Project Directory Structure

Each project has this structure:

```
projects/[project_name]/
│
├── README.md                      # Project overview & metadata
├── metadata.json                  # Project configuration
│
├── input/                         # 📥 Input files
│   ├── README.md                  # Instructions
│   ├── transcript.txt             # Meeting transcript
│   └── metadata.json              # Project metadata
│
├── workflow_execution/            # 🔄 Pipeline results (auto-generated)
│   ├── 01_flattened/              # Flattened markdown chunks
│   │   ├── meeting_summary.md
│   │   ├── risks_issues.md
│   │   ├── deliverables.md
│   │   ├── timeline.md
│   │   ├── budget.md
│   │   └── metadata.yaml
│   │
│   ├── 02_intake_output.json      # Extracted KPIs
│   ├── 03_prioritized_output.json # Ranked KPIs
│   ├── [project]_Status_Report.html # Final report
│   └── README.md                  # Execution notes
│
└── output/                        # 📤 Output files (if needed)
    └── [project]_Status_Report.html
```

## File Descriptions

### README.md (Each Project)
**Purpose**: Project overview and metadata

**Contains**:
- Project name and client
- Key dates and milestones
- Team members
- Project status
- Any special notes

**Update**: Whenever project status changes

### metadata.json (Each Project)
**Purpose**: Machine-readable project configuration

**Fields**:
- `project_name` - Full project name
- `practice` - PMO, QMS, ITQC, etc.
- `client_name` - Client organization
- `go_live_date` - Target go-live date
- `timeline_status` - ON_TRACK, AT_RISK, DELAYED
- `budget_total` - Total project budget
- `budget_spent` - Amount spent to date

**Update**: Before running pipeline

### input/ - Input Files
**Purpose**: Store input data for pipeline

**Contents**:
- `transcript.txt` - Meeting transcript
- `transcript.vtt` - Optional VTT format
- `metadata.json` - Project configuration
- Any supporting documents

**Guidelines**:
- Keep transcripts clean and readable
- Ensure metadata.json is valid
- Include all required fields

### workflow_execution/ - Pipeline Results
**Purpose**: Store complete pipeline execution results

**Auto-generated by pipeline**:
- `01_flattened/` - Flattened markdown chunks
- `02_intake_output.json` - Extracted KPIs
- `03_prioritized_output.json` - Ranked data
- `[project]_Status_Report.html` - Final report

**DO NOT manually edit** these files. They are generated by the pipeline.

**README.md notes**:
- When executed
- Which version of code
- Any issues encountered
- Next steps

## Common Tasks

### Run Pipeline for a Project
```bash
python run_pipeline.py \
  --transcript projects/[project]/input/transcript.txt \
  --metadata projects/[project]/input/metadata.json \
  --project-name "[Project Name]"
```

### View Generated Report
```bash
open projects/[project]/workflow_execution/[project]_Status_Report.html
```

### Update Project Status
1. Edit `projects/[project]/README.md`
2. Update `timeline_status`, dates, team info
3. Commit to git

### Archive Completed Project
```bash
mv projects/[project] archive/archived_2026_q3/[project]
```

## Project Naming Conventions

Use consistent naming:

**Format**: `[client_firstname_lastname]` or `[company_name]`

**Examples**:
- ✅ `stephenson_rife` - Law firm
- ✅ `galfand_berger` - Law firm
- ✅ `acme_corp` - Corporation
- ✅ `tech_startup_inc` - Tech company

**Guidelines**:
- Use lowercase
- Use underscores (not hyphens)
- Be descriptive
- Avoid abbreviations if possible

## Best Practices

✅ **DO**:
- Keep project folders organized
- Update README when status changes
- Store transcripts in `input/`
- Let pipeline manage `workflow_execution/`
- Document any special requirements
- Archive completed projects
- Use consistent naming

❌ **DON'T**:
- Manually edit pipeline outputs
- Store large files outside projects
- Mix projects together
- Delete old projects (archive instead)
- Commit `workflow_execution/` to git
- Leave projects in unclear state
- Use inconsistent naming

## Archiving Projects

When project is complete:

```bash
# Move to archive
mv projects/[project_name] archive/archived_2026_q3/[project_name]

# Or create quarterly archive folder first
mkdir -p archive/archived_2026_q3
mv projects/[project_name] archive/archived_2026_q3/
```

**Archive structure**:
```
archive/
├── archived_2026_q1/
│   ├── stephenson_rife/
│   ├── galfand_berger/
│   └── README.md (index of archived projects)
└── completed_projects/
    └── [old projects]
```

## Troubleshooting

### Pipeline Can't Find Files
- ✅ Check path is correct
- ✅ Verify `transcript.txt` exists
- ✅ Verify `metadata.json` is valid JSON

### Generated Files Are Empty
- ✅ Check API key is set
- ✅ Check transcript has content
- ✅ Check metadata fields are filled

### Can't Find Project Report
- ✅ Check `workflow_execution/` folder
- ✅ Verify pipeline ran successfully
- ✅ Check project name in command
